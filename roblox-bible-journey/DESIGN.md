# 예수님의 길 (The Journey) — 로블록스 성경 게임 설계서

어린이(만 8~12세 중심)가 **예수님의 생애를 순서대로 따라가며** 성경을 자연스럽게 익히는
로블록스 경험. "퀴즈로 시험 보는 성경 공부"가 아니라 **이야기 속 인물이 되어 겪는 여정**.

---

## 1. 설계의 중심 결정 3가지

먼저 이 세 가지를 정하지 않으면 나머지가 다 흔들립니다.

### 1-1. 플레이어는 예수님이 아니다 — "따라가는 아이"다

플레이어는 **그 시대의 한 아이**입니다. 베들레헴에서 태어나 여정 내내 예수님을 따라다니는
목격자·제자 역할. 예수님은 플레이어 아바타로 만들지 않습니다.

이유가 셋:

| 이유 | 설명 |
|---|---|
| 신학적 존중 | 예수님을 조작 가능한 캐릭터로 만들면 스킨·점프·춤 이모트가 붙습니다. 부모와 교회가 가장 먼저 문제 삼는 지점 |
| 로블록스 모더레이션 | 실존 종교 인물의 부적절한 묘사는 정책 위반 소지. 조작 불가 NPC로 두면 리스크가 거의 사라짐 |
| 게임 디자인 | "따라가는 자"가 되면 **순종·관찰·섬김**이 곧 게임 메커닉이 됩니다. 주인공이면 그게 불가능 |

**표현 방식**: 뒤에서 본 모습, 먼 거리의 실루엣, 빛/음성/발자국. 얼굴 클로즈업 없음.
카메라가 예수님을 정면으로 담지 않는 규칙을 렌더링 레벨에서 고정.

### 1-2. 진도는 "길"로 보이게 한다 (허브 앤 로드)

"쭉 나아가지는 느낌"이 이 게임의 핵심 요청인데, 아이들은 **숫자 진행도(12/18 완료)를 못 느낍니다.**
대신 **월드 자체가 길어지게** 만듭니다.

```
[갈릴리 언덕 허브]
   │
   ├─ 걸어온 길: 포장됨, 등불 켜짐, 지나온 장면의 미니 디오라마가 길가에 서 있음
   │
   └─ 앞의 길: 안개에 덮여 있음 → 챕터 클리어 시 안개가 한 구간 걷힘
```

- 아이가 로그인하면 **자기가 걸어온 거리를 눈으로 봅니다.** 이게 진행도 UI보다 100배 강합니다.
- 길가 디오라마는 지나온 챕터를 **재방문 가능한 입구**로 씁니다 (복습을 강제하지 않고 유혹).
- 앞길의 안개는 다음 챕터를 **궁금하게** 만듭니다. 잠금 아이콘보다 훨씬 좋음.

### 1-3. 십자가는 "플레이"하지 않는다

여기서 게임이 죽거나 삽니다. 아이용 콘텐츠에서 채찍질·못·피는 **절대 안 됩니다.**
로블록스 모더레이션도, 학부모도 통과 못 합니다.

대신 **구레네 시몬의 시점**을 씁니다:

- 플레이어는 무거운 십자가의 **한쪽을 함께 드는** 역할. 무게 때문에 걷기가 느려지는 물리 감각만 남김.
- 골고다에 도착하면 **화면이 어두워지고 조작이 멈춥니다.** 언덕 위 세 개의 실루엣이 멀리, 역광으로.
  피·상처·비명 없음. 정적과 어둠, 그리고 찢어지는 성전 휘장 소리 하나.
- 그 다음 챕터가 **부활**이므로, 어둠은 3~4분만 유지됩니다. 아이를 슬픔에 방치하지 않는 게 중요.

## 2. 챕터 구성 — 18장 여정

각 챕터는 **8~12분**. 아이 집중 시간과 로블록스 세션 길이(평균 15~20분)에 맞춘 길이입니다.

| # | 챕터 | 성경 | 메커닉 (이야기가 곧 규칙) |
|---|---|---|---|
| 0 | 기다림 | 이사야 예언 | 튜토리얼. 허브에서 조작 배우기. "오래 기다린 약속" 프롤로그 |
| 1 | 베들레헴의 밤 | 눅 2 | **양치기 몰이** — 별을 따라 양떼를 마구간까지 유도 |
| 2 | 동방에서 온 사람들 | 마 2 | **별 항법** — 밤하늘 별자리를 맞춰 길 찾기 |
| 3 | 성전의 소년 | 눅 2:41 | **숨은 사람 찾기** — 인파 속에서 12살 예수를 찾는 3일 (부모 시점의 조급함) |
| 4 | 요단강 | 마 3 | **타이밍 리듬** — 세례 요한을 도와 사람들을 물로 안내 |
| 5 | 광야 40일 | 마 4 | **말씀 카드 방어** ★ 핵심 시스템. 아래 3-2 참고 |
| 6 | 그물을 던져라 | 눅 5 | **낚시** — 혼자선 빈 그물. "깊은 데로 가서 던져라" 순종 후 성공 |
| 7 | 가나의 잔치 | 요 2 | **물동이 운반 옵비** — 6개 항아리를 깨지 않고 채우는 협동 |
| 8 | 산 위에서 | 마 5 | **팔복 정원** — 여덜 개 씨앗을 심으면 각각 다른 식물로 자람 (실시간 성장) |
| 9 | 지붕을 뜯고 | 막 2 | **4인 협동** — 친구 넷이 들것 네 귀퉁이를 잡고 지붕으로. 혼자선 불가 |
| 10 | 오병이어 | 요 6 | **나눔 물류** ★ 5000 NPC 배식. 내가 가진 걸 내놓을수록 늘어남 |
| 11 | 폭풍 위에서 | 막 4 | **평온 유지** — 패닉해서 뛰면 배가 흔들림. 가만히 있는 게 정답인 유일한 챕터 |
| 12 | 씨 뿌리는 자 | 마 13 | **네 가지 땅** — 같은 씨를 4곳에 심고 며칠 뒤 결과 확인 (실시간 24h) |
| 13 | 잃은 양 하나 | 눅 15 | **99마리 두고 1마리** — 우리에 99마리 넣고 끝내려 하면 문이 안 닫힘 |
| 14 | 나사로야 나오라 | 요 11 | **빛의 귀환** — 무덤 앞, 어둠에서 빛으로. 감정 챕터 |
| 15 | 종려나무 길 | 마 21 | **행렬** — 서버의 모든 플레이어가 동시에 참여하는 퍼레이드 이벤트 |
| 16 | 마지막 저녁 | 요 13 | **세족** ★ 다른 실제 플레이어의 발을 씻어줘야 진행. 아래 3-3 참고 |
| 17 | 겟세마네 / 골고다 | 마 26~27 | **깨어 있기 → 함께 짊어지기** (위 1-3 규칙 적용) |
| 18 | 빈 무덤 | 요 20 | **새벽** — 어두운 정원에 해가 뜨는 5분. 조작 최소, 음악과 빛만 |
| 19 | 가서 전하라 | 마 28 | **엔딩 → 안내자 승급** 아래 4-3 참고 |

**MVP는 18장 다 만들지 마세요.** 1장 + 6장 + 10장 + 허브. 이 셋이 각각
`탐색형` / `순종형` / `협동형` 원형을 대표하므로, 이것만으로 전체 루프가 검증됩니다.

## 3. 학습이 작동하는 3개 시스템

"재미있는데 아무것도 안 배움"을 막는 장치들입니다. 퀴즈는 하나도 없습니다.

### 3-1. 말씀 조각 (Verse Fragments)

- 각 챕터에서 구절을 **한 번에 다 주지 않고 3~4조각으로 쪼개** 맵에 숨깁니다.
- 조각을 모으면 허브의 **등불**이 밝아집니다. (경쟁 지표 아님, 개인 성장 지표)
- 조각은 **다음 챕터에서 실제로 쓰이는 도구**가 됩니다. 이게 핵심.

### 3-2. 말씀 카드 방어 — 게임에 박아넣은 인출 연습 ★

5장(광야의 시험)이 이 시스템의 교과서입니다.

```
사탄: "네가 하나님의 아들이면 이 돌들에게 명하여 떡이 되게 하라"
  ↓
플레이어 손패: 지금까지 모은 말씀 조각 6장
  ↓
정답 카드: "사람이 떡으로만 살 것이 아니요" (신 8:3)
```

- 아이는 **자기가 직접 주워 모은 구절**로 시험을 막습니다.
- 이건 퀴즈가 아니라 **전투 시스템**입니다. 아이는 카드를 이기려고 외웁니다.
- 5장 이후에도 각 챕터 보스/난관에서 계속 재등장 → **간격 반복 학습(spaced retrieval)** 이
  게임 진행 그 자체가 됩니다.
- 오답 페널티는 체력 감소 같은 게 아니라 **"다시 생각해볼까?" 힌트 + 재시도**. 실패 처벌 금지.

### 3-3. 남을 섬겨야 열리는 문 (Co-op Gates)

성경 교육 게임이 흔히 놓치는 것: **머리로 알기와 몸으로 하기의 차이.**

3개 챕터를 **다른 실제 플레이어가 있어야만** 클리어되게 설계합니다.

- **9장** 중풍병자 들것: 4명이 각자 한 귀퉁이. 3명이면 들것이 기울어져 떨어짐.
- **10장** 오병이어: 내 도시락을 바구니에 넣으면 **내 것은 줄고 서버 전체 배식량이 늘어남.**
  아무도 안 내놓으면 5000명이 안 먹습니다. 순수 사회적 딜레마 → 대화가 발생.
- **16장** 세족: 다른 플레이어 앞에 무릎 꿇는 이모트를 해야 진행. 그 플레이어도 나에게 해줘야 함.

혼자 접속했을 때는 NPC가 대신하지만 **보상 등불이 흐리게** 표시됩니다.
"친구랑 하면 더 밝아진다"는 걸 UI로 알려주는 것 → 자연 바이럴.

## 4. 계속 나아가게 만드는 리텐션 설계

### 4-1. 하드 락 대신 소프트 게이팅

챕터는 순서대로 열리되, **한 번 연 챕터는 영구히 재방문 가능**. 되돌아가기를 막으면
아이가 막힌 곳에서 이탈합니다. 대신 "지나온 길은 밝고 걷기 쉽다"로 재방문을 유도.

### 4-2. 매일 돌아올 이유

| 장치 | 내용 |
|---|---|
| 오늘의 씨앗 | 접속 시 씨앗 1개. 허브 정원에 심으면 24시간 후 성장 → **다음날 접속 이유** |
| 실시간 성장 챕터 | 8장(팔복 정원), 12장(네 가지 땅)은 결과가 다음날 나옴 |
| 주간 행렬 | 15장 종려나무 퍼레이드를 주 1회 서버 전체 이벤트로 상시 운영 |
| 로블록스 배지 | 챕터별 네이티브 배지. 아이들에게 프로필 배지는 화폐입니다 |

### 4-3. 엔딩 = 안내자 승급 (제일 중요한 루프)

19장 "가서 전하라"를 클리어하면 **게임이 끝나지 않고 역할이 바뀝니다.**

- **안내자(길잡이)** 자격을 얻습니다. 허브에서 신규 플레이어에게 표시되는 등불 아이콘.
- 신규 플레이어를 챕터에 데려가 도와주면 **안내 횟수**가 쌓입니다.
- 이게 게임의 진짜 엔드게임 콘텐츠이고, 동시에 **대사명(마 28:19)의 게임적 번역**입니다.
  주제와 리텐션 메커닉이 완전히 일치하는, 이 프로젝트에서 가장 좋은 아이디어.

### 4-4. 절대 넣지 말 것

- ❌ **경건함 리더보드.** "누가 구절을 더 많이 외웠나" 랭킹은 이 게임의 주제를 정면으로 배신합니다.
  리더스탯은 `등불` `함께한 횟수`만, 그리고 **정렬하지 않습니다.**
- ❌ **스토리 구간 유료화.** 아래 6절 참고.
- ❌ **연속 접속 끊김 페널티.** 아이가 죄책감을 느끼는 구조는 이 장르에서 특히 해롭습니다.

## 5. 로블록스 기술 설계

### 5-1. 단일 Place로 시작하세요

멀티 Place(`TeleportService`)는 매력적으로 보이지만:

- 텔레포트마다 로딩 화면 → 8세 아동 이탈 지점
- **플레이어가 18개 Place로 흩어짐** → 협동 게이트(3-3)가 전부 무력화. 이게 치명적입니다.

**권장**: `StreamingEnabled = true` 단일 Place. 챕터 맵은 `ReplicatedStorage`에
모델로 두고 진입 시 서버가 스폰. 메모리 한계(모바일 기준 ~1GB)에 부딪히면
그때 "구약/신약" 2개 Place로 쪼개면 됩니다.

### 5-2. 챕터 모듈 계약

모든 챕터가 같은 인터페이스를 구현하면 18장 확장이 복붙 수준으로 떨어집니다.

```lua
--!strict
-- ServerScriptService/Chapters/Chapter01_Bethlehem.lua

local Chapter = {}
Chapter.id = "ch01_bethlehem"
Chapter.title = "베들레헴의 밤"
Chapter.reference = "누가복음 2:1-20"
Chapter.fragments = { "ch01_f1", "ch01_f2", "ch01_f3" }
Chapter.requires = { "ch00_waiting" }        -- 선행 챕터
Chapter.minPlayers = 1                        -- 협동 게이트 챕터는 4
Chapter.estimatedMinutes = 9

-- 세션 시작. 맵 스폰, NPC 배치, 목표 UI 전달
function Chapter.start(session: Session): ()
end

-- 매 프레임 아님. 목표 달성 이벤트가 들어올 때만 호출
function Chapter.onObjective(session: Session, objectiveId: string): ()
end

-- 정리. 어떤 경로로 끝나든(클리어/이탈/서버종료) 반드시 호출 보장
function Chapter.cleanup(session: Session): ()
end

return Chapter
```

`ChapterService`가 이 모듈들을 `requires`로 위상 정렬해서 여정 그래프를 자동 생성합니다.
챕터 추가 = 파일 하나 추가.

### 5-3. 진행도 저장 — 여기서 게임이 죽습니다

**아이가 진도를 잃으면 그 아이는 돌아오지 않습니다.** 날 `DataStoreService`를 직접 쓰지 마세요.
세션 락 없이 쓰면 두 서버가 동시에 같은 프로필을 덮어씁니다.

- **ProfileStore**(구 ProfileService) 사용. 세션 락 + 자동 재시도 + 리컨실리에이션 제공.
- 스키마 버전 필드를 처음부터 넣으세요. 나중에 챕터 구조를 바꿀 때 마이그레이션이 필요합니다.

```lua
local PROFILE_TEMPLATE = {
    schema = 1,
    completedChapters = {},   -- { ch01_bethlehem = 1738... (완료 시각) }
    fragments = {},           -- { ch01_f1 = true, ... }
    lampLevel = 0,
    guideCount = 0,           -- 안내자로 도운 횟수
    lastSeedAt = 0,
    locale = "ko",
}
```

- **진행도 판정은 100% 서버 권한.** 클라이언트가 "클리어했어요"를 보내는 구조는
  로블록스 익스플로잇 스크립트가 하루 만에 뚫습니다. 서버가 목표 상태를 직접 관찰해야 합니다.
- 오토세이브는 이벤트 기반(챕터 완료, 조각 획득) + 이탈 시 강제 플러시.

### 5-4. 개발 환경

| 항목 | 권장 |
|---|---|
| 코드 관리 | **Rojo** + VS Code + Git. Studio 안에서만 작업하면 리뷰·롤백이 불가능 |
| 타입 | Luau `--!strict` 전면 적용. 18챕터 규모에서 타입 없으면 리팩터가 지옥 |
| 패키지 | Wally (ProfileStore, Promise, Signal) |
| 테스트 | TestEZ로 `ChapterService` 진행도 로직 유닛 테스트. 맵은 못 테스트해도 **진행도 그래프는 반드시** |
| 에셋 | 툴박스 무료 에셋은 **스크립트가 심어진 경우가 실제로 있습니다.** 가져오면 `Script`/`LocalScript`/`RemoteEvent` 전수 검사 후 사용 |

### 5-5. 읽기 능력 문제 — 텍스트에 의존하지 마세요

주 타겟 중 상당수가 **긴 문장을 안 읽습니다.** (이 리포의 paint-mix-sort에서
"텍스트가 아니라 손가락으로 가르친다"는 커밋과 같은 원칙)

- **내레이션 음성 필수.** 로블록스는 6초 초과 오디오를 **자기 소유 경험에서는 사용 가능**하므로
  내레이션을 붙일 수 있습니다. (타 경험 공유는 불가)
- 텍스트는 한 화면 **2줄 이내**. 나머지는 음성 + 아이콘 + NPC 손짓.
- 목표 표시는 항상 **월드 안의 화살표/빛기둥**으로. 화면 상단 텍스트 목표는 안 읽힙니다.

### 5-6. 다국어 — 처음부터 준비

한국어만 하면 도달 범위가 로블록스 전체의 몇 %로 제한됩니다. 이 콘텐츠는
전 세계 교회 수요가 확실히 있는 주제입니다.

- 하드코딩 문자열 금지. 처음부터 `LocalizationService` + 문자열 키 테이블.
- 1차: 한국어 + 영어. 2차: 스페인어, 포르투갈어 (로블록스 최대 비영어권).

## 6. 반드시 확인해야 할 실무 리스크

### 6-1. 성경 번역 저작권 ⚠️

**개역개정·새번역·쉬운성경 등 한국어 주요 번역본은 대한성서공회 저작권**이 있습니다.
게임에 구절 원문을 그대로 넣으면 허락이 필요합니다.

- **안전한 길**: 아이 눈높이로 **직접 의역**하고 출처만 표기 (`요한복음 3:16`).
  성경 장·절 참조 자체는 저작권 대상이 아닙니다.
- 원문을 꼭 쓰려면 대한성서공회에 사용 허락 문의 (비영리 교육 목적은 승인 사례 있음).
- 영어는 **WEB, KJV가 퍼블릭 도메인**이라 자유롭게 사용 가능.

### 6-2. 로블록스 모더레이션

- 종교 콘텐츠 자체는 허용됩니다. 문제는 **폭력 묘사**(1-3 규칙 준수)와 **실존 인물 묘사**(1-1 규칙 준수).
- Content Maturity 설문에서 "경미한 폭력/무서운 이미지" 항목을 정직하게 신고하세요.
  숨기다 걸리면 경험 전체가 내려갑니다.
- 커스텀 채팅 시스템 만들지 마세요. `TextChatService` 기본 필터를 쓰면 모더레이션 책임이 로블록스에 있습니다.
- **자유 입력 기도 게시판 같은 기능 금지.** 필터를 통과한 나쁜 문장은 반드시 나옵니다.
  대신 **정해진 문구 선택형** ("기도할게요" / "고마워요" / 이모트)로 대체.

### 6-3. 수익화

교육/선교 목적이라면:

- **스토리 챕터에 결제 게이트를 걸지 마세요.** 이 게임에서 가장 평판을 망치는 선택입니다.
- 필요하다면 **순수 코스메틱**(등불 스킨, 시대 의복)만. 확률형(가챠)은 절대 금물.
- 로블록스 정책상 경험 내에서 **실제 기부·후원 유도는 금지**입니다. 교회 계좌 안내, 외부 링크 모두 위반.

## 7. 로드맵

| 단계 | 기간(추정) | 산출물 |
|---|---|---|
| **P0 프로토타입** | 2~3주 | 허브 + 1장(양치기) 하나. Rojo 세팅, ProfileStore 연결, 진행도 저장 검증 |
| **P1 수직 슬라이스** | 4~6주 | 1·6·10장 + 말씀 카드 시스템 + 협동 게이트 1개. **비공개 테스트로 실제 아이 5~10명** |
| **P2 1막 출시** | 8~12주 | 0~10장(탄생~오병이어), 한/영, 배지, 오늘의 씨앗 |
| **P3 2막** | +8주 | 11~19장(비유~승천), 안내자 승급 시스템 |
| **P4 운영** | 상시 | 주간 행렬 이벤트, 절기 콘텐츠(성탄·부활절), 언어 추가 |

**P1 끝에서 반드시 실제 아이들에게 테스트하세요.** 성인이 설계한 성경 게임이 실패하는
1번 원인은 "아이가 어디서 지루해하는지 몰랐다"입니다. 관찰 포인트:

1. 어느 지점에서 처음 딴짓을 하는가 (그게 잘라낼 구간)
2. 텍스트를 읽는가, 넘기는가 (넘기면 음성/시각으로 대체)
3. 말씀 카드를 **이기려고** 구절을 보는가 (그렇다면 학습 시스템이 작동하는 것)
4. 게임 후에 이야기를 **자기 말로 다시 말할 수 있는가** ← 진짜 성공 지표. 구절 암송보다 중요

## 8. 성공 지표

암기량으로 측정하지 마세요. 이 게임의 목적은 **이야기의 순서와 의미가 몸에 남는 것**입니다.

| 지표 | 목표 | 왜 |
|---|---|---|
| 1장 완주율 | > 70% | 첫 챕터에서 못 붙들면 나머지가 무의미 |
| D1 / D7 리텐션 | > 35% / > 15% | 로블록스 교육 카테고리 기준 양호선 |
| 챕터당 이탈 지점 | 각 챕터 이탈 < 15% | 특정 챕터가 튀면 그 챕터가 지루하거나 어려움 |
| 협동 게이트 성공률 | > 60% | 낮으면 동시 접속자 부족 → 챕터 설계 재조정 |
| 이야기 재진술 | 테스트 아동 다수 성공 | **최상위 지표.** 정성 평가지만 이게 전부 |
| 안내자 전환율 | 완주자의 > 20% | 엔드게임 루프 작동 여부 |
